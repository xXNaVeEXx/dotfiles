# Staffelübergabe und Neustart einer Spur-Sitzung

## Staffelübergabe (eigener Kontext reicht nicht mehr, Faltung scheitert, Nachtlauf zu lang; oder ganzer Plan für eine neue Orchestrator-Sitzung, die ich nur beaufsichtige)
Laufende eigene Worker abschließen, keine neuen starten. Dann `.tmp/night/ORCH-AUFTRAG.md` (Auftrag wörtlich, bereits getroffene Entscheidungen, Queue, Ablauf je Paket, Regeln für Übergabe und Abschluss, Obergrenze teurer Worker je Anbieter-Konto, bei der Orchestrator und Aufsicht mitzählen) und eine Übergabe-Notiz schreiben. Neue Sitzung: `herdr tab create --workspace <ws> --cwd <dir> --label orch-<n> --no-focus` (Pane-ID in `.result.root_pane.pane_id`), dann `herdr agent start orch-<n> --kind pi --pane <pane> -- --model <provider/id> --thinking high` (Pane muss am Shell-Prompt stehen) und `herdr agent wait <pane> --until idle`. Vor dem Startprompt den Bildschirm per `herdr pane read <pane> --source visible` auf Warn-Dialoge prüfen: Ein Skill mit YAML-Fehler fehlt sonst still (Fix und Prüfskript in pi-extension-dev §12), danach `herdr agent prompt <pane> "/reload"`. Den Startprompt aus einer Datei schicken: `herdr agent prompt <pane> "$(cat <datei>)" --wait --until working --timeout 30000`. Grund: Ein langer Startprompt in der pi-Befehlszeile bricht an Anführungszeichen, und erst nach dem Laden ist sichtbar, ob alle Skills da sind. SID aus `herdr agent get <pane>` (`.result.agent.agent_session.value` = Pfad der Sitzungs-JSONL). Den Watchdog über eine von ihm eingelesene `watchdog.env` (Pane, SID) auf die neue Sitzung umstellen. Danach selbst nichts mehr am Projekt tun. Grund: Zwei Orchestrator-Sitzungen am selben Baum kommen sich in die Quere. Jede ältere Übergabe-Notiz im Ordner bekommt als erste Zeile `ÜBERNOMMEN von <Pane>/<SID> um <Zeit> – Stand: PLAN.md`; ist der Vorgänger schon weg, schreibt sie der Nachfolger. Grund: Startet der Nutzer später eine Sitzung mit der alten Notiz, hält diese den alten Stand für aktuell und arbeitet im selben Baum neben dem Nachfolger.

## Spur-Sitzung mit übervollem Kontext
Bricht wiederholt nach abgelehnter Faltung ab und versucht trotz Regel Block-Zusammenführungen: nicht weiter anstoßen, sondern zwischen zwei Paketen in einem NEUEN herdr-Tab neu starten (gleicher Worktree, gleiche `--env`-Werte), die PANE-Datei der Spur umstellen (alte als `PANE.alt-<pane>` sichern), eine Startdatei mit Regeln, Auftrag, Plan-Ende und Ist-Stand (Branch, Commits, laufende Worker) prompten, die Aufsicht neu starten und die alte Sitzung untätig liegen lassen. Grund: Eine frische Sitzung lädt nur das Nötige, bekommt neu installierte Erweiterungen (Abbruch-Fortsetzung) und erbt keinen kaputten Faltungszustand.
